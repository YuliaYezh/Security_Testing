# Security_Testing
# Тестирование безопасности веб-ресурсов 

Работа выполнена в образовательных целях, с согласия владельца ресурсов (в рамках учебного курса). Название и ip ресурса заменены в целях безопасности. 
Комплексный проект по тестированию безопасности трёх веб-ресурсов:  
`1111.ru`, `2222.ru`, `3333.ru`.

Цель работы - сбор информации, сканирование уязвимостей и моделирование проникновения во внутреннюю сеть.

## Методология

Работа построена по принципу **многоэтапного пентеста**:

1. **Пассивная разведка** (OSINT) - сбор публичной информации без активного взаимодействия с серверами:  
   - DNS-запросы (`host`, `Dnsdumpster`)  
   - Анализ заголовков и технологий (`whatweb`)  
   - Поиск скрытых каталогов (`robots.txt`, `sitemap.xml`)  
   - Google Dorks для поиска уязвимых страниц  

2. **Активное сканирование** - прямое взаимодействие с сетевыми службами:  
   - Обнаружение открытых портов и сервисов (`nmap`)  
   - Определение версий ПО и ОС  
   - Проверка базовых уязвимостей  

3. **Проникновение во внутреннюю сеть** - эмуляция действий злоумышленника на изолированном стенде:  
   - Сканирование локальной сети (`netdiscover`)  
   - Подбор учётных данных по SSH (`hydra`)  
   - Анализ веб-уязвимостей (`nikto`)

## Используемые инструменты

| Инструмент | Назначение |
|------------|-----------|
| `host` | Получение IP-адреса по доменному имени |
| `whatweb` | Распознавание веб-технологий, CMS, серверов |
| `Dnsdumpster` | Просмотр DNS-записей и поддоменов |
| `robots.txt` / `sitemap.xml` | Выявление скрытых разделов |
| Google Dorks | Поиск конфиденциальной информации в индексе Google |
| `nmap` | Сканирование портов, сервисов и ОС |
| `netdiscover` | Обнаружение хостов в локальной сети |
| `nikto` | Поиск веб-уязвимостей |
| `hydra` | Брутфорс паролей по SSH |

## Результаты

### Часть 1: Пассивная разведка

**Цель:** Собрать максимум информации о целевых ресурсах без активных запросов.

#### `1111.ru`
- **IP:** `11.111.111.11`, `11.111.111.11`
- **Веб-сервер:** nginx/1.14.1
- **CMS:** TYPO3 4.5
- **Бэкенд:** PHP/5.6.27
- **Обнаруженные поддомены:** через Dnsdumpster найдено 8 записей в AS `ERTH-PENZA-AS`
- **Куки:** `fe_typo_user`
- **robots.txt:** отсутствует → потенциальный риск скрытой информации
- **Google Dorks:** найдены страницы входа (`/auth/login`)

#### `2222.ru`
- **IP:** `22.222.222.22`
- **Сервер:** nginx/1.14.1, PHP/7.4.12
- **CMS:** Moodle
- **Библиотеки:** jQuery 3.5.1
- **Куки:** `MoodleSession` (HttpOnly)
- **robots.txt:** блокирует Amazonbot, но разрешает основные поисковики
- **sitemap.xml:** доступен

#### `3333.ru`
- **IP:** `33.333.333.33`
- **Технологии:** Flask (Werkzeug), Bootstrap 3.3.7, jQuery 1.12.4
- **Редиректы:** цепочка через `/DDoS01/...` и на `/auth/login`
- **Куки:** `session` (HttpOnly)
- **robots.txt:** отсутствует

### Часть 2: Активное сканирование

**Цель:** Проверить открытые порты, сервисы и версии ПО.

#### `1111`
- **Открытые порты:**
  - `53/tcp` - DNS (bind)
  - `80/tcp` - HTTP (nginx 1.14.1)
  - `443/tcp` - HTTPS (nginx 1.14.1 с SSL)
- **ОС:** не определена (из-за защитных механизмов)

#### 2222`
- Открыты только `80` и `443` → веб-сервис работает корректно, других служб не обнаружено.

#### `3333`
- Сканирование не дало детальной информации (возможно, скрыто за DDoS-защитой).

---

### Часть 3: Проникновение во внутреннюю сеть

**Цель:** На виртуальном стенде получить доступ к внутренней сети под любым пользователем.

**Исполнение:**
1. `netdiscover -i eth1` - найден целевой хост.
2. `nmap -sS -sV -O` - открыты порты:
   - `22/tcp` (SSH) - OpenSSH 8.2p
   - `80/tcp` (HTTP) - веб-сервер
3. Добавлен IP в `/etc/hosts` для локального разрешения.
4. `nikto -h` - выявлены потенциальные уязвимости (например, отсутствие некоторых заголовков безопасности).
5. Подбор пароля по SSH (`hydra`) — успешно подобран пароль для пользователя `user`, получен доступ к системе.

## Выводы

- **Наибольшая информация** собрана по основному домену `111.ru`.
- **Используемые защитные меры:** редиректы через `/DDoS01/`, HttpOnly-куки, блокировка роботов, но есть слабые места (отсутствие `robots.txt`, открытые почтовые адреса, старые версии ПО).
- **Потенциальные риски:**
  - Устаревший PHP 5.6 на `111.ru`.
  - Открытые DNS-зоны, позволяющие узнать структуру сети.
  - На тестовом стенде показана возможность брутфорса SSH-паролей → рекомендуется внедрение двухфакторной аутентификации и блокировка после нескольких неудачных попыток.
